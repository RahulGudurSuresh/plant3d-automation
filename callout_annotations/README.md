# callout_annotations — full P&ID line numbers on Plant 3D orthos

Plant 3D's *Full Line Number Callout* prints `Size-LineNumberTag-Spec`
(`80-209M01-SFSA`). The P&ID — the mother document — names the same pipe
`217-209-080-WCG-SFSA-NN`. Service, area and insulation code were never
entered in the 3D model, so no annotation style can show them.

This tool reads the ortho DWG **and** the P&ID PDF, joins them on the line
sequence number, and writes one callout per visible pipe run carrying the
**full P&ID name**, in every view, with a leader to the pipe. Lines it
cannot resolve get a **red** label a human has to clear — it never guesses.

## Environment

Uses the **shared** virtualenv one level up (`../../.venv`, Python 3.11) —
see `../../requirements-shared.txt`. Do **not** create a `.venv` here.
Needs the free ODA File Converter for DWG↔DXF
(`winget install ODA.ODAFileConverter`).

```powershell
& "d:\AI_Rahul\Automation\.venv\Scripts\python.exe" -m callout_annotations.cli `
    "inputs\Plan view.dwg" inputs\PID-Binder.pdf --out out --png
```

Outputs in `out\`:

| File | What |
|---|---|
| `Plan view_CALLOUTS.dwg` | the ortho with callouts (open in Plant 3D / AutoCAD) |
| `report.md` | read this first: what needs a human, what was resolved by size |
| `report.csv` | one row per line tag: status, label, P&ID candidates, views, callout count |
| `<view>.png` | one picture per view, drawn from the same model the placer used |

Tests: `python -m pytest tests` (the pipeline test needs `inputs\`).

## How it works

```
P&ID PDF ──► pid.py     text layer → every string matching the site grammar
                        area-seq-DN-service-spec-suffix   (500 names, 22 sheets)

Ortho DWG ─► oda.py     DWG → DXF
         ──► ortho.py   one INSERT per component on layer "<view>-<tag>";
                        each view's linework is flattened into a WCS plane
                        (plan Z=0, sides X=0, front/back Y=0) and shown by a
                        paper-space viewport. ViewFrame = (u,v,n) per view.

              match.py  tag 209M01 → seq 209 → P&ID names with seq 209
                          unique     → callout
                          by-size    → callout (two names, sizes differ,
                                       linework OD picks one)
                          ambiguous  → RED callout "<tag> ? 214-540-080 / 217-540-050"
                          missing    → RED callout "<tag> NOT IN P&ID"

              place.py   THE RULE: a callout that cannot be placed legibly is
                         worse than none.  Pass 1, plan view first: each run
                         gets a callout only where it is CLEAN -- no other
                         label under it (hard ban), little pipe/equipment
                         linework under it (steel and grating count less),
                         short leader.  Pass 2: a P&ID line named nowhere is
                         forced into its least-bad spot and flagged.  Text is
                         written with an AutoCAD background mask.

              writeback.py  MTEXT (+ LEADER) in model space, in the view's
                         plane: insert = WCS, text_direction = +u, extrusion
                         = n. Layers "<view>-CALLOUT" / "-CALLOUT-REVIEW",
                         frozen in every viewport that hides that view.
                         Re-runs delete the previous callouts first.
```

## Layout

| Path | Purpose |
|---|---|
| `callout_annotations/config.py` | `Site` (regexes, layer names) and `Tuning` (weights). The only place conventions live |
| `callout_annotations/pid.py` | PDF → `PidIndex` |
| `callout_annotations/ortho.py` | DXF → `ViewFrame`s, `Run`s, obstacle index; OD estimate |
| `callout_annotations/match.py` | the join and its four outcomes |
| `callout_annotations/place.py` | pure 2D placement |
| `callout_annotations/writeback.py` | DXF output + viewport freeze bookkeeping |
| `callout_annotations/report.py` | CSV + Markdown |
| `callout_annotations/cli.py` | the pipeline |
| `tools/render_views.py` | per-view PNGs of the placer's own model (fast, agrees with the placer by construction) |
| `tools/render_paper.py` | **the honest check**: one view rendered from the real DXF entities with real fonts, as its viewport shows it |
| `tools/sweep_gate.py` | dry placement under a different gate, counts only |
| `tools/tidy_with_isotidy.py` | trial bridge to isotidy's solver (superseded by the gate; kept for the record) |
| `tests/` | unit tests + regression over `inputs/` |
| `inputs/` | the JP1071 sample (M-02 plan ortho + P&ID binder) |

## What it does not do

* **Write into Plant 3D's project database.** The callouts are plain MTEXT,
  not Plant 3D annotation objects, so they do not follow the pipe if the
  model changes and are not regenerated by *Update View*. That needs the
  project folder (`Piping.dcf`) or an in-process plugin — see `CONTEXT.md`.
* **Read a scanned P&ID.** The binder must have a text layer; the CLI stops
  if it finds none.
* **De-conflict against Plant 3D's own annotations** — this drawing had
  none. If a drawing does, they are linework to the placer (avoided) but
  not moved.
